# 그래픽 파이프라인 — 3D → 도트 스프라이트

캐릭터·소품을 3D로 만들고 애니메이션을 준 뒤, 저해상도로 렌더해서 도트 스프라이트로 굽는다.
실시간 3D 렌더 방식은 쓰지 않는다 (모든 그래픽은 미리 구운 2D 스프라이트).

## 확정 사양
| 항목 | 값 |
|---|---|
| 엔진 | Unity 2022.3 LTS, URP 2D Renderer |
| 캐릭터 크기 | 64px |
| 방향 | 8방향 (렌더는 5방향 + 좌우 반전이 기본, 비대칭 캐릭터는 8방향 전체) |
| 기본 게임 해상도 | 640×360 (1080p 3배, 1440p 4배, 4K 6배 정수 확대) |
| 팔레트 | 캐릭터당 16~24색, 게임 전체 32~64색 |
| 텍스처 설정 | Filter Point, 압축 None, PPU 프로젝트 전체 통일 |
| 미정 | 시점(아이소메트릭 64×32 타일 / 탑다운 32×32 타일) → 정해지면 카메라 각도 확정 |

## 역할 분담
- **기획자(직접)**: 3D 모델링, 리깅, 애니메이션, Aseprite 수작업 보정
- **스크립트(Claude)**: Blender 일괄 렌더, 팔레트 양자화·외곽선·시트 패킹, Unity 임포트 자동화, 8방향 애니메이터

## 1. 모델링 규칙
- 로우폴리 + 단색 텍스처. 정한 팔레트 색으로 칠한다 (세밀한 텍스처는 노이즈가 됨).
- 비율 과장: 머리·손·무기를 크게. 64px에서도 실루엣이 읽혀야 한다.
- **원점은 발밑**, 정면은 Blender -Y 방향.
- 사람형 키는 1.8m로 통일 → 같은 카메라로 전부 64px 안에 들어옴. 큰 몬스터는 캔버스를 키워서 따로 렌더.
- 반전으로 작업을 줄이려면 디자인을 좌우 대칭에 가깝게.

## 2. 애니메이션 규칙
- Mixamo 자동 리깅·기본 동작 사용 가능, Blender에서 수정.
- **제자리(In Place)** 모션.
- 액션 이름: `idle`, `walk`, `attack`, `hit`, `die` 처럼 영문 소문자로 통일 (스크립트가 이름으로 처리).
- 프레임 수 적게: 걷기 6~8, 공격 4~8. 2~3프레임 간격 렌더 또는 Constant 보간으로 끊어지는 느낌.
- 공격은 예비 동작과 타격 프레임을 과장.

## 3. Blender 렌더 세팅
- 정사영(Orthographic) 카메라 고정, **모델(루트 Empty)을 45°씩 회전** → 조명 방향이 화면 기준으로 일정.
- 목표 해상도로 바로 렌더 (고해상도 렌더 후 축소 금지).
- Film → Filter Size 최소(0.01px), 배경 Transparent.
- 툰 셰이딩: EEVEE `Shader to RGB → Color Ramp(Constant)`, 명암 2~3단계.
- 카메라 각도와 Ortho Scale은 캐릭터·소품·타일 **모두 동일**하게.
- 피벗(발 위치)은 모든 방향·프레임에서 같은 픽셀.

## 4. 조명
- 고정 분위기 조명 → 렌더에 구워 넣기. (이 경우 좌우 반전 금지, 8방향 전체 렌더)
- 게임 속 움직이는 광원 → 패스 분리 렌더:
  - Albedo: 조명 없이 평평한 색
  - Normal: 노멀맵 (Albedo와 같은 해상도, 안티앨리어싱 없음)
  - Emission: 발광 부위 마스크 (다른 텍스처 남는 채널에 합쳐도 됨)
- Unity: Sprite Secondary Textures에 `_NormalMap`, `_MaskTex` 등록 + 2D Light.
- 조명 결과는 2~4단계로 끊는 셰이더(Shader Graph)로 도트 느낌 유지.
- 반전 방향은 노멀맵 X(빨강) 채널도 뒤집혀야 함.

## 5. 후처리와 보정
- 고정 팔레트로 양자화, 디더링 끄기.
- 1px 외곽선, 여백 제거(Trim), 스프라이트 시트로 패킹.
- Aseprite 보정은 **키 포즈 위주**: 얼굴·눈, 외톨이 픽셀, 계단 선, 이펙트 추가.
- 보정 우선순위: 정면(하) > 좌우 > 대각 하단 > 뒷모습 쪽(가볍게).
- 실루엣을 크게 바꾼 프레임은 노멀맵도 맞춰 수정.

## 6. 맵
- 바닥·벽·지형: 타일셋 + Unity Tilemap (모듈형 3D 조각을 타일 크기로 렌더해도 됨).
- 건물·나무·큰 소품: 3D에서 개별 스프라이트로 렌더.
- 원경: 레이어별로 렌더해서 패럴랙스 배경.
- 캐릭터와 같은 카메라 각도·Ortho Scale·팔레트·광원 방향. 배경은 채도·대비를 살짝 낮춤.

## 7. Unity 적용
- 카메라에 Pixel Perfect Camera, 기준 해상도 640×360.
- 정수배 확대만 사용.
- 손실 GPU 압축(DXT, ASTC) 금지 — 도트 경계가 번짐.
- 파일 위치는 CLAUDE.md 규칙을 따른다: `Assets/Art/<분류>/<영문소문자_밑줄>.png`
  - 예: `Assets/Art/characters/knight_walk.png`, `knight_walk_n.png`(노멀), `knight_walk_e.png`(발광)

## 8. 용량 참고 (캐릭터 1명, 동작 6 × 8방향 × 8프레임 = 384장)
| | 설치 용량(PNG) | 메모리 | 노멀맵 포함 |
|---|---|---|---|
| 64px | 약 1~2MB | 약 6MB | 약 12MB |
- 5방향 + 반전이면 약 40% 절약. 아틀라스 + Trim으로 30~60% 추가 절약.
- 스테이지(전투)에 등장하는 캐릭터만 로드.

## 시작 순서
1. 캐릭터 1명 + 모션 2개(걷기, 공격)로 Blender → 변환 → Unity까지 끝까지 한 번 돌려본다.
2. 카메라 각도·크기·색감 문제를 여기서 잡는다.
3. 이후 캐릭터는 같은 설정으로 찍어낸다.
