# 작업 규칙 (모든 스레드 엄수)

확정: 2026-10-30 런들님. 바꿀 땐 개발_작업규칙 스레드에서 런들님 확인 후.

## 기본
1. 정보 없이 코딩하지 않기. 먼저 묻고, 같이 계획하고, 구현한다.
2. 무조건 동의하지 않기. 문제와 대안을 먼저 검토한다.
3. 기본 테스트만으로 "완료" 금지. 직접 실행해 화면을 보고, 런들님이 플레이하기 전엔 끝이 아니다.
4. 같은 실수 반복 금지. 실수는 rules/실수기록.md와 개발_작업규칙 스레드에 한 줄씩 적는다.
5. "작업해"/"진행해" 전엔 반영(굽기, 파일 수정 등) 금지. 의견 교환부터 한다.
6. 답변은 항상 한국어.
7. 스레드 이름은 "분류_주제" (게임/개발/아트).
8. 작업 단위가 끝날 때마다 git 기록(커밋)을 남긴다. 되돌릴 땐 그 기록으로 돌아간다. 커밋은 개발_작업규칙 스레드에 바뀐 파일 목록을 보내 요청한다.
9. 일을 시작하기 전에 rules/작업규칙.md와 rules/실수기록.md를 읽는다.

## 실수에서 나온 규칙
10. 지적·요청은 대기 목록에 적고, "작업해"/"진행해" 후에 한 번에 진행한다. 지적은 승인이 아니다.
11. 지울 대상은 확정된 목록만 지운다. 미확정은 남긴다. 지울 땐 휴지통으로.
12. 기본값을 코드에서 바꾸면 실제 설정 파일 값도 Inspector에서 확인한다.
13. 새 방식은 미리보기로 한 프레임 확인한 뒤 전체 굽기.
14. 타격 프레임 등 자동 판정은 미리보기로 런들님 확인 후 확정.
15. 결과 보고는 수치 + 눈으로 본 비교 이미지 + 런들님 확인. 수치만으로 "완료" 금지.
16. Unity 메뉴는 열 때마다 화면을 보고 누른다. 예전 좌표로 누르지 않는다.
17. 공유 폴더에 쓴 뒤 10초 기다렸다 다시 읽고 확인한 다음 기기로 보낸다.
